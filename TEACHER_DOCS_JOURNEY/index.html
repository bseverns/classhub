    Teacher Docs Journey¶

    Summary¶

    This is the recommended wiki read path for teachers and assistants. It is designed for non-developers: short, practical, and ordered by "what you need right now."

    What to do now¶

    1. Start with the 10-minute path below.
    2. Use the full read order when you have 30-45 minutes.
    3. Keep this page bookmarked as your "where do I read next?" index.

    Verification signal¶

    A first-time teacher should be able to answer "What do I do before class, during class, and after class?" in under 15 minutes of reading.

    If you only have 10 minutes¶

    1. START_HERE_INSTRUCTOR.md: what ClassHub is, what success looks like.
    2. RUN_A_CLASS_TOMORROW.md: exact steps for a live class day.
    3. COMMON_SCENARIOS.md: what to do when something breaks.
    4. LESSON_OVERRIDES.md: how to make a reversible class-specific lesson change without editing shared curriculum files.

    Full teacher read order (30-45 minutes)¶

    Step Read this page Why it matters When to return to it
    1 START_HERE_INSTRUCTOR.md Sets expectations and core goals. New teacher onboarding.
    2 RUN_A_CLASS_TOMORROW.md Gives a concrete session checklist. Before each class day.
    3 NON_DEVELOPER_GUIDE.md Explains normal classroom workflows in plain language. Weekly refresh or when coaching a new assistant.
    4 LESSON_OVERRIDES.md Shows how to make class-only lesson edits without changing shared curriculum files. When one class needs a temporary or local variation.
    5 TEACHER_PORTAL.md Deep reference for screens, routes, and exports. When you need exact UI details.
    6 COMMON_SCENARIOS.md Fast decision tree for real-world problems. Mid-session issue handling.
    7 TROUBLESHOOTING.md Operational triage with health checks and recovery steps. Escalations or repeated failures.
    8 RISK_AND_DATA_POSTURE.md Explains privacy/data boundaries in non-technical language. Stakeholder or parent questions.

    Mental model that helps this stick¶

    • Before class: use RUN_A_CLASS_TOMORROW.md.
    • During class: use NON_DEVELOPER_GUIDE.md + COMMON_SCENARIOS.md.
    • After class: use TEACHER_PORTAL.md for closeout and exports.
    • If there is an outage or blocker: use TROUBLESHOOTING.md.

    Suggested onboarding script (for leads)¶

    Read this to a new teacher in 60 seconds:

    "You do not need to learn the whole system at once. Start with START_HERE_INSTRUCTOR, run tomorrow with RUN_A_CLASS_TOMORROW, and keep COMMON_SCENARIOS open during class. If you need exact button-level details, use TEACHER_PORTAL. If something truly breaks, move to TROUBLESHOOTING."
